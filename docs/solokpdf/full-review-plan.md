## 対象と深さ

対象は Windows 版 SolokPDF の構造とコード。
確認の深さは、各評価観点で見つかった問題、その影響、関連実装の複雑さに応じて判断する。

全ファイルの台帳化、全ダイアログ・基盤ライブラリの同一深度での精読は行わない。
ビルド・生成・依存管理とテスト基盤は独立した監査工程にせず、対象経路の判断や変更に必要な範囲で確認する。
第三者ライブラリ内部は問題の追跡に必要な場合だけ読む。

`src/ng/` の機能開発、D3 の CI 分割、F1/F3 の実機確認、配布、DLL 登録試験、クラッシュ復旧の実地検証は対象外・保留を維持する。
共有コードの変更候補では ng の呼び出し側への影響を確認する。
印刷・画像出力も、構造や契約の確認に必要な関連実装を追う。

## 評価観点

操作経路は調査を進める手掛かりとし、対象範囲や評価観点を限定する条件にはしない。
下表の観点で確認し、問題が疑われる箇所は関連実装へ追う。

| 観点               | 確認すること                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| 責務と依存         | 処理の担当、層の境界、依存方向、循環・密結合、UI から内部への直接アクセス                                   |
| API 契約と正しさ   | 契約自体の妥当性、引数・戻り値・副作用の意味、呼び出し側との整合性、正常・空・部分取得・失敗・中止の扱い    |
| 状態と寿命         | 状態の所有者、所有・借用の有効期間、遷移、結果の公開・無効化・破棄、例外・早期終了時の解放                  |
| 非同期処理と同期   | スレッド間の受け渡し、ロック順、競合、再入、遅延通知、キャンセルと終了待ち                                  |
| 処理の構造と保守性 | 判断・処理の重複、不必要な複雑さ、過剰な抽象化、暗黙の前提、命名と処理の追いやすさ                          |
| データの整合性     | 表現・変換・座標・単位・長さの対応、元入力と編集結果の区別、キャッシュ間の整合性                            |
| 性能と応答性       | 不要な読み込み・コピー・再計算、メモリ保持、ロック競合、UI スレッドの長時間処理・待機                       |
| 検証可能性         | 重要な分岐・失敗条件を既存テストが確認しているか、assertion・skip・タイミング依存、再現と追加検証のしやすさ |

なるべくコードや構造はシンプルにする。利用者に必要な動作とデータの整合性を保ちつつ、部品の契約・責務・境界を変える再構成も検討する。
現行の契約を維持する案と変更する案を、全体の複雑さ、変更の影響、移行・検証の負担で比較する。複雑さを別の部品へ移すだけの変更は避ける。
構造上の問題は具体的な依存・重複・変更時の誤りやすさで説明する。
性能はコードから判断できる不要な処理や待機を先に確認し、効果量やトレードオフが判断に必要な場合だけ測定する。

## 操作経路ごとの確認

以下を主な手掛かりとして進める。UI、エンジン、共有処理、既存テストを一緒に確認し、表にない処理も関連すれば追う。

| 順序 | 操作経路                 | 主な確認事項                                                                                                                                    |
| ---- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 開く・読み取り・移動     | flags・設定からエンジン選択、パスワード、元入力の保持、テキスト・要素・リンク・目次取得まで。文書フォールバック、未取得・部分取得・失敗の契約   |
| 2    | 描画・表示変更           | 表示・ズーム・テーマ変更から要求、描画、後処理、タイル反映まで。ページ描画代替、注釈合成、色入力、世代、Home・F12・Merge PDF のサムネイルとの差 |
| 3    | 入力・コマンド・画面状態 | キー・マウス・コマンドから検索・選択・移動・編集への配送。優先順位、フォーカス、モード、タブ・ポップアップ状態、遅延通知と再入                  |
| 4    | 編集・Undo/Redo          | 注釈・フォーム・文書 JavaScript・署名・墨消しから編集生成、文書変更、再描画まで。権限、生成失敗、UI とエンジンの役割、状態の無効化              |
| 5    | 保存・複製・再読み込み   | 元入力と編集結果、保存先とファイル実体、複製時の所有権、元ファイルの移動・置換、再読み込み時の要求・キャッシュの扱い                            |
| 6    | 閉じる・終了             | タブ・ウィンドウ・文書の破棄、設定・セッション保存、要求中止、ワーカー・UI 投稿・サムネイルの終了待ちと参照解放                                 |

各経路では正常系に加え、空・未取得・権限不足・非対応・失敗・中止・再入のうち実際に存在する分岐を追う。
上記の評価観点を使い、UI・エンジン・共有処理をまたぐ契約と実装の整合性を確認する。

文字列・コンテナー・ファイル処理などの基盤は、対象経路の使い方を確認し、前提や寿命に疑問があれば実装へ追う。
既出の描画終了待ち、`EnginePdfium` の責務集中、`RenderCache` の描画担当もこの中で判定する。変更の必要性は事前に決めない。

## 各経路に組み込む確認

既存テストの assertion と skip を読み、操作・失敗条件の何を実際に検証しているかを確認する。
タイミング依存や検証不足を記録し、再現・判断に必要なテストだけ実行する。
runner、制御プロトコル、非表示デスクトップなどの内部は検証を妨げる問題がある場合に追う。
週次 ASan の起動確認など、経路レビューと独立した CI 運用点検は追加しない。

コード変更が必要になった場合は、影響に応じてビルド登録、生成元と出力、DLL・ランタイム配置、構成差を確認する。
MuPDF の変更には同じ変更のパッチ記録を伴わせる。依存の版・更新処理全体の監査は行わない。

## 指摘と検証

各指摘に場所、コード上の根拠または再現条件、影響、既存テスト、最小変更案、検証方法を残す。
「不具合」「契約・責務の問題」「検証不足」「変更不要」を区別し、疑いは未確定として記録する。
優先順位はデータ損失・寿命・競合・停止、動作の不整合、変更時の誤りを招く構造の順。
ファイルの大きさや TODO だけで変更を決めず、分割・統合・全面的な再構成も含め、全体をよりシンプルにできるかで判断する。

修正はレビュー結果と分けた小さな差分にする。不具合は既存テストを優先し、不足する重要な失敗はテストを先に作り、失敗を確認してから修正する。
構造変更は維持する動作と対象テストを先に決め、画素への影響は出力比較、寿命・所有権の変更は ASan も確認する。
現在の表示品質を損なわない。描画結果が変わる変更は、その必要性と見え方への影響を確認する。

実行手順は [testing.md](testing.md)。ローカルは Debug・必要時 ASan、GUI は非表示デスクトップ、アドホック起動は `-for-testing`。
Release は GitHub Actions のみ。全スイートは明示的な依頼時だけ実行する。不安定なテストは単独で複数回比較する。
実行した検証は revision・差分・構成・入力・結果・skip・ログを残し、過去の結果や未実行と区別する。
整形・生成・パッチ登録は `agents.md` に従い、コミットは明示的な指示後に行う。

会話が中断したら、再実行前に turn の状態・エラー、残存プロセス、保存済み成果を確認する。
安全判定で失敗した同じ実験は自動再試行しない。具体的な判定対象は不明で、再発防止の保証はできない。
当面はコード精読と対象の既存テストでレビューを進め、新しい再入・障害再現は修正時の専用回帰試験へ分ける。
結果はケース終了直後に保存し、GUI は個別の制限時間と対象画面を確認した終了手順を使う。
失敗したケースがあっても独立した調査と記録は進める。
