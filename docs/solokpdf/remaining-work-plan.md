## 1 CI の失敗調査と静的チェック

- **D15 の事前調査**。11月16日の手動実行2件について、選択されたエンジン、テスト名、失敗ステップをジョブログや成果物から確認する。
  取得できない場合は run ID と確認できた範囲を履歴に残し、E151 と現行コードの検証を進める。
  [該当する実行記録](history.md#hosted-validation-and-status-review-2026-11-18)
- **E151 Markdown・CHM**。`ad-hoc-e144-focus-restores` のページ b から c への遷移で、
  コマンド受信、論理ページ、ブラウザへの遷移要求、`TestMarkdownServed` に載る要求、前面・アクティブ・フォーカスを同じ時系列に記録する。
  失敗時の順序を制御できるテストにし、遷移の実装とテストのどちらで止まるかを特定する。
  両形式でページ c の要求が届いてフレームまたはキャンバスにフォーカスが戻り、ページ b では別ウィンドウに置いたフォーカスが保たれれば完了。
  ローカルは隠しデスクトップ、対話デスクトップ固有の条件は hosted Windows で確認する。
  [対象テスト](../../tests/ad-hoc-e144-focus-restores.ts)
- **E152 ng と静的チェック**。`lint-fz-catch` の再帰走査と、全件テストの `lint-control-ids` が読む対象を調べる。
  SolokPDF 実行時の対象を Win32 と共有コードに揃え、既存の呼び出し元も確認する。
  一時フィクスチャで ng だけの違反が SolokPDF のチェック結果に影響せず、対象内の同等の違反が失敗することを確認する。
  [MuPDF lint](../../tests/lint-fz-catch.ts) · [制御 ID lint](../../tests/lint-control-ids.ts)

## 2 エンジン競合時の応答性

- **E129 引用プレビュー**。カーソル判定と表示タイマーを、キャッシュ済み結果と処理中の状態を扱う読み取り経路に揃える。
  未抽出ページやロック保持中も UI が応答し、取得後にマウスを動かさず表示が更新され、PDFium の編集エンジンが未生成のままであることを確かめる。
  抽出失敗、タブ切り替え、文書クローズも確認し、長文のプレーンテキスト引用は抽出完了から表示までを測る。
  [ホバーの回帰テスト](../../tests/ad-hoc-e120-busy-hover.ts)
- **E132 読み取り API**。E129 で揃えた呼び出しを基に、ホバーと明示操作の入口を型で分ける。
  誤った入口の使用や、処理中の結果を空として扱うコードをコンパイル時に検出できる形にする。
  型で表せない検査を既存 lint に残し、ホバー、フォーム、クリックの結果が従来どおりであることを確認する。
  [操作の回帰テスト](../../tests/ad-hoc-e123-busy-actions.ts)
- **E133 キャンセル対象の棚卸し**。操作が待つロックと、その保持元を対応付ける。タイル、サムネイル、引用プレビュー、
  MuPDF の表示リスト、PDFium のテキスト抽出・ウィジェット描画、印刷・書き出しについて、キャンセル点と復帰方法を記録する。
- **E134 注釈操作**。注釈の色・内容を変更する経路から、競合時のキャンセルをロック取得境界へ集約する。
  PDFium の編集描画と MuPDF の描画をそれぞれ停止させた状態で操作し、変更が反映され、キャンセル後に描画が戻ることを確認する。
  ロック順と PDFium のプロセス共通ロックを確認し、既存のフォーム編集と Undo/Redo も対象にする。
- **E133 残りの処理**。棚卸しで見つかった各保持元を一つずつ制御し、操作に応答した後に再描画・再要求・処理再開まで確認する。
  印刷や PDFium の途中中断できない API は、保持が続く区間と中断できる境界を記録する。
  待ち時間とキャンセル確認までの区間を測り、残る待ちに根拠のある上限を示せる範囲を明記する。
  [既存の描画停止テスト](../../tests/ad-hoc-e128-busy-render.ts) · [現行の制約](limitations.md)

## 3 ポップアップの位置とフォーカス

- **E117 テスト入力**。入力層で Windows のヒットテスト、カーソル、ボタン、キャプチャ、キー状態、活性化の順序を再現する。
  Run PDF Script の例選択とスタイルメッセージを別々に検証し、残るモーダルとアンカー付きトップレベル窓へケースを追加する。
  隠しデスクトップの `rightHalf` と `workArea` の両方で確認し、別プロセスの実前面が必要なケースは hosted Windows に残す。
  [デスクトップ依存の確認](testing.md#desktop-dependent-checks)
- **E112 位置追従**。検索バーの基準点の移動、スクロール、ズーム、表示切替を共通の再配置経路で扱う。
  文書やタブの置き換えでは一度だけ閉じることを確認し、OS による一時非表示と区別する。
  スクロール中の再評価回数と処理時間を計測して、再配置が必要なときだけ実行されることを確かめる。
  [配置の回帰テスト](../../tests/ad-hoc-e98-anchored-popups.ts)
- **E125 注釈ツールバー**。クリック位置を選択状態と同じ寿命で扱う。
  注釈の左端から離れた位置をクリックし、スクロールで画面外に出して戻す、最小化から復元する、別タブから戻る、の各操作で元の位置に出ることを確認する。
  選択を変えたときは新しい選択の位置を使う。
  [注釈ツールバーの回帰テスト](../../tests/pdf-edit-toolbar-interaction.ts)
- **E126 Home のキーボードチップ**。復元時に対象項目のフォーカスを確認してチップを表示する。
  最小化の両順序で、同じフォーカスなら復元し、項目が変われば古いチップが出ず、ホバー用チップはカーソルに従うことを確認する。
  [配置の回帰テスト](../../tests/ad-hoc-e98-anchored-popups.ts)

## E154 通知の上書きと Esc

`039e4ec60` でテーマ通知をズームと同じグループに載せ、Esc で閉じられるようにした。
上書きの単位を変えずに Esc の対象を指定できるよう、通知の作成時に閉じる可否と優先順位を別に指定する。
通知層が対象を選んで閉じ、フレーム側は検索バーなどの UI 操作と通知をどの順に処理するかを決める。
まず SolokPDF で共通処理を整え、ng は開発再開時にその処理を使う。

非表示デスクトップの Debug で、ズームとテーマの前後切り替えをそれぞれ Esc で閉じられることを確認する。
複数表示時は優先対象を一つだけ閉じ、同一グループの通知は従来どおり上書きすることを確かめる。
別のウィンドウや非表示タブの通知、検索バーとの順序、ページ情報を閉じた後の状態も確認する。
[既存のテーマ操作テスト](../../tests/ad-hoc-theme-keyboard.ts)

## 検証と完了

1. 不具合は対象テストで修正前の失敗と修正後の成功を確認する。GUI は隠しデスクトップ上の Debug、所有権やスレッド寿命の変更は必要に応じて ASan でも確認する。
   PDFium と MuPDF の共通経路は両エンジンで試す。PDFium の既定設定と PDF の描画品質を維持し、Release は GitHub Actions でのみビルドする。
   [ローカルの検証手順](testing.md#local-windows-runs)
2. **D15**。対象テストが通ったコードで通常 CI を確認する。全件検証は明示指示がある場合に hosted Debug を PDFium・MuPDF 各1回、hosted ASan を1回実行し、対象コミット、
   run ID、エンジン、除外・失敗ケースを記録する。同じコミットで両エンジンの全件対象と ASan の対象が通れば D15 を完了とする。
   [全件テストの手順](testing.md#hosted-full-suite) · [ASan CI](testing.md#asan-ci)
3. 完了条件を満たした項目を履歴へ移し、影響した挙動や手順の文書を更新する。未再現・未確認の条件は、次に必要な証拠とともにバックログへ残す。
   [記録先](history.md#completed-backlog)
