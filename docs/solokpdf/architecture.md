# SolokPDF の現行設計

E21 の色方針、E19 の描画結果、E22 のキャッシュ、E18 の読み取り契約、E20 の文書寿命を反映した Win32 版の責務と状態。
初回点検は [レビュー結果](full-review-results.md)、評価基準は [レビュー計画](full-review-plan.md)、完了済みの見直しは [リファクタリング計画](refactoring-plan.md)、
実装・検証履歴は [history.md](history.md) を参照する。

## PDF エンジンの役割

PDFium と MuPDF は文書全体で排他的に切り替わるものではない。
通常の本文は PDFium が描画し、必要な操作だけ MuPDF が担当する。

| 経路                          | 判断する場所                                                                                              | 役割                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 文書を開く                    | [EngineCreate.cpp](../../src/shared/EngineCreate.cpp)                                                     | PDFium の失敗時に MuPDF で文書を開く。パスワード入力の中止など、再試行しない失敗を区別する |
| ページを描く                  | [EnginePdfium.cpp](../../src/solokpdf/EnginePdfium.cpp) の `PrepareRenderRoute`、`DrawPage`、`RenderPage` | ページの内容・テーマ変換の可否に応じて描画経路を選ぶ。文書全体のエンジンは変えない         |
| 注釈・フォームを編集する      | `AnnotationEditor`、[EngineMupdf.cpp](../../src/shared/EngineMupdf.cpp) の `AnnotEngineMupdf`             | 同じ文書の編集エンジンを遅延生成する。文書 JavaScript や一部の読み取りにも使う             |
| テーマ・特殊な PDF 情報を扱う | [EngineAll.h](../../src/shared/EngineAll.h) の PDF 用 API                                                 | 描画用プローブ、テーマ変換、ページ形状など。遅延編集エンジンとは別の用途                   |

注釈描画はタイルごとに編集エンジンの有無を一度読み、二重描画を避ける。
墨消し適用後のページは編集エンジンが描画・読み取りを担当する。
編集前の元データのコピーと、編集内容の保存・再読み込みは別の操作である。
詳細は [annotations.md](annotations.md#design) を参照する。

## 描画と色処理

`CapturePageColors` がプレビューを含む有効モードを一度取得し、[Theme.cpp](../../src/shared/Theme.cpp) の
`ThemePageRenderColors` に渡して色反転を含む実効色を取得する。
このモード・前景色・背景色・リンク色を `PageColorInput` として、通常描画と Home のサムネイルが保持する。
[PdfDarkModeProfile.cpp](../../src/shared/PdfDarkModeProfile.cpp) の分類別プロファイル生成は、
この値だけを参照し、設定やテーマを読み直さない。
`CaptureViewOptions` はこの色入力とグレースケールを UI スレッドで取得する。
`UpdateDocumentColors` が同じ値を `RenderCache::SetViewColors` に渡し、
要求は描画開始時に色・グレースケール・補正値と世代を保持し、色プロファイル生成にその値を使う。
F12 と Merge PDF のサムネイルも UI 側で色を取得してワーカーへ渡す。
Merge PDF は従来どおりファイル別補正・グレースケールを適用しない。
[Pixmap.cpp](../../src/base/Pixmap.cpp) の `RecolorPageColor` と `RecolorPixmap` は同じ画素変換を使う。
PDF の色空間から RGB への変換と、テーマ色への変換は別の処理である。

| 経路                                    | 現在の処理                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------------- |
| PDFium の smart                         | MuPDF でページの色を変えた一時 PDF を作り、PDFium が描画する。変換に失敗した場合は MuPDF 描画を使う |
| MuPDF の smart・PDFium の代替・注釈合成 | MuPDF の描画デバイスを通して色を変える。マスクなど元の色を保つ条件を持つ                            |
| PDF の smart の表示後処理               | エンジン内で色変換後、`RenderViewPage` がグレースケール、明度・コントラスト補正を行う               |
| legacy の表示後処理                     | `RenderViewPage` が補正後、ビットマップを再着色する                                                 |
| F12 ページサムネイル                    | `RenderPageThumbnail` が `RenderViewPage` を使う                                                    |
| Home の保存済みサムネイル               | 中立 PNG を複製し、補正後に再着色する。画像保持は保存した矩形による近似                             |

`8bf864e18` で集約した `GetPageColorPass` がエンジン分類・入力元・プロファイルから
色変換の担当を `None`・`Renderer`・`Bitmap` で返す。
[RenderViewPage](../../src/shared/RenderCache.cpp) と Home のサムネイルがこの方針を使う。
PDF の smart は描画側、Home の中立画像はビットマップ側で変換する。
これは予定する段階の指定。実施状態は `RenderPageArgs::color_out` の
`RenderPageColor::Original`・`Themed` で成功時だけ返す。呼び出し側は `Original` で初期化する。
PDFium と MuPDF が描画時の変換を報告し、`RenderViewPage` は変換済みの画素を再着色しない。
引数のコピーにローカルなプロファイルと出力先を渡し、呼び出し元に一時ポインターを残さない。

`PrepareRenderRoute` の `PdfRenderRoute` は経路判定。
`DrawPage`・`DrawMupdf` の `PageDrawResult` は完了・代替要求・中止・失敗と色状態を返す。
PDFium の進行状態は `DrawPage` 内だけで扱い、代替要求だけを `DrawMupdf` で再実行する。
ビットマップ生成・通常ページ読み込み・PDFium 描画の失敗を、一律に代替要求には変えない。

描画先は背景を埋めた BGRA8 の借用バッファ。PDFium は straight alpha、MuPDF の代替は
乗算済み alpha を生成し、`Pixmap::hasAlpha`・`premultiplied` が後処理を決める。
透明な PDFium 出力だけを一度乗算し、その後に編集エンジンの注釈を合成する。
不透明な View 出力は従来どおり gray DIB または BGR8 に縮める。
成功した `Pixmap` は呼び出し側が所有し、失敗・中止・注釈合成失敗では解放して null を返す。
MuPDF も結果公開前に中止を確認する。テーマ・PDFium ロックの範囲と画素後処理の並列性は維持する。

## キャッシュと無効化

| 保存する値                              | 再利用条件・出力への依存                                                                                            | 無効化と寿命                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `RenderCache` の最終画素                | 文書・ページ/Location・タイル・ズーム・回転・色世代。世代は実効モード・前景/背景/リンク色・グレースケールに対応する | 色変更は世代を進める。補正値・編集は対象文書/ページの要求を中止し、既存画素を古い表示として扱う          |
| PDFium のテーマ変換 PDF                 | 同じ入力文書のページ・前景/背景/リンク色。smart 描画だけが使う                                                      | エンジンの寿命内で保持。テーマ復帰時も再利用する。中止した変換は保存しない                               |
| PDFium の描画経路・ページ形状・画像矩形 | 元文書とページ。色・グレースケール・補正値から独立                                                                  | テーマ変更では破棄しない。再読み込みは新しいエンジンを作る                                               |
| MuPDF の画像保持矩形                    | ページ内画像・ズーム・回転。既存の options hash も確認する                                                          | ページ解放・編集・レイヤー変更で破棄。既存のテーマ変更時リセットも維持する                               |
| F12 ページサムネイル                    | 文書・ページ・サイズ・回転・確定した `ViewPageOptions`                                                              | 色変更/タブ変更はキャッシュを切り離す。補正・編集の Refresh は世代を進め、古いワーカー結果を受け入れない |
| Home の中立 PNG と画像矩形 sidecar      | ファイル・サイズ・エンジン分類・保存時の画像矩形。表示テーマから独立                                                | テーマ変更では保持。ファイルの更新時刻・明示削除・新しいサムネイルへの置換で無効化する                   |
| Home の表示用コピー                     | プロファイル hash・グレースケール・ファイル別の明度/コントラスト                                                    | UI スレッドで中立 PNG から作り直す。元 PNG・分類・矩形の置換時はコピーも解放する                         |

`SetViewColors` は要求ロック、キャッシュロックの順で入力と世代を公開する。
要求取得は同じ要求ロックでスナップショットを保持する。
タイル挿入は両ロック内で中止・世代を確認してから既存タイルを置き換える。
これにより、描画後の確認と挿入の間に色変更や編集が起きても、新しいタイルを古い結果で失わない。
UI の完了通知も色世代を確認し、古いテーマの失敗で現在のページを描画失敗にしない。
選択色だけの変更と透明グリッド切替も、従来どおりタイル世代を進める。

PDFium のテーマキャッシュは変換後の PDF を持ち、タイル世代は最終画素の有効性を表す。
明度・コントラスト・グレースケール・ズームは変換 PDF のキーに加えない。
4 エントリー・64 MiB の LRU と、単一の大きい変換結果を残す扱いは維持する。
hash と世代は役割が異なり、統一しない。

注釈・フォームは遅延編集エンジンの合成結果をページ単位で再描画する。
墨消し適用済みページは元文書の変換結果・画像矩形を使わず、編集エンジンへ委ねる。
Undo で元文書へ戻る場合は、保持したテーマ変換結果を再利用できる。
再読み込みは古い要求を中止し、新エンジンへ切り替える。既存のタイルは一時表示用にだけ残す。

## 所有権と同期

| 所有するもの                                          | 現在の責務                                                                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| [PdfiumRuntime](../../src/solokpdf/PdfiumRuntime.cpp) | DLL API、ライブラリ初期化・参照数、フォントキャッシュ。利用者がゼロでも DLL は保持する                                            |
| `EnginePdfium`                                        | PDFium 文書・ページ情報、入力バイト列またはファイル、パスワード、遅延編集エンジン、描画プローブ、テーマキャッシュを保持・解放する |
| `gPdfiumLock`                                         | 文書をまたぐ PDFium API とランタイムの操作を直列化する                                                                            |
| `editorLock`                                          | 遅延編集エンジンの初回生成を保護する。生成結果は atomic なポインター操作で公開する                                                |
| `themeLock`                                           | 描画経路の準備とテーマキャッシュの利用を保護する。`DrawPage` はこの後に `gPdfiumLock` を取る                                      |
| `fileLock`                                            | ファイルからの位置指定読み取りを保護する                                                                                          |

パスワード問い合わせ中は `gPdfiumLock` を解放する。ダイアログのメッセージ処理中に
他の PDFium 操作が再入し得るため、この順序も設計の一部である。

### 元データと借用の寿命

`dataBacked` は添付 PDF などの入力元を表し、メモリ保持の有無とは異なる。
通常ファイルも 32 MiB 未満なら `fileData` に保持する。
パスは表示名・保存先として使い、遅延編集・複製・印刷設定・補助リンクの入力は保持中の元データから読む。
通常の「名前を付けて保存」もエンジンの元データをコピーする。
ファイル保持時は出力を切り詰める前にハンドルの実体を比較し、移動後の元ファイルやハードリンクへの自己コピーでは書き込まない。

| 対象                              | 所有と借用                                                                                                                                         | 解放条件                                                                                                  |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 元データ                          | `EnginePdfium` が `fileData` または共有読み書き・削除を許すファイルハンドルを所有する。PDFium の `FPDF_FILEACCESS` はエンジンを借用する            | PDFium 文書と描画プローブを閉じてから解放する                                                             |
| PDFium 文書・フォーム・ページ情報 | エンジン所有。ページ・描画用ビットマップは呼び出し内で閉じる。ページ情報はエンジン寿命まで保持する                                                 | フォームを文書より先に閉じ、最後にランタイム参照を返す                                                    |
| 遅延編集                          | メモリ入力は MuPDF がコピーする。大きい入力は `CreateEngineMupdfFromHandle` が同じファイル実体を独立した位置のハンドルで開き、ストリームが所有する | エンジンは編集への参照を1つ保持する。墨消し済みの複製などが参照を持てば、編集は PDFium より長く生存できる |
| 描画プローブ                      | 専用 MuPDF 文書・コンテキストを所有し、読み取り元のエンジンを借用する                                                                              | `themeLock` 内で使用。中止時またはエンジン破棄時に解放する。呼び出し後はキャンセル先を消す                |
| テーマ変換結果                    | エンジンが変換済みバイト列を所有する。一時 PDFium 文書は元データと変換結果を借用する                                                               | `themeLock` 内で一時文書を閉じてから、キャッシュを置換・解放できる                                        |
| 補助読み取り                      | `PdfRenderSource` は呼び出し元を借用する。印刷設定・OpenAction・補助リンクの一時 MuPDF 文書は関数内だけで使用する                                  | 文書とストリームを返却前に解放し、借用を外へ残さない                                                      |
| TOC・要素・テキスト               | 編集由来の TOC・要素は編集エンジンから借用する。PDFium 自身の要素はエンジン所有、抽出テキストは呼び出し側所有                                      | 借用 TOC を PDFium 側で二重解放しない。テキストキャッシュの借用は無効化まで                               |

名前変更・削除・同名ファイルへの置換では、保持したバイト列またはファイル実体を使い続ける。
大きいファイルを同じ実体のまま上書きする場合は不変スナップショットではなく、従来どおり再読み込みが必要。
ハンドルを開き直せなければ、別のパスの文書へ切り替えず失敗する。

### 状態遷移

| 操作                  | 状態と無効化                                                                                                                                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 開く・開く途中の失敗  | 入力、ランタイム、文書を順に取得する。途中まで取得したものも通常のデストラクターで解放する                                                     |
| 編集生成・生成失敗    | `editorLock` 内で生成し、成功後だけ atomic に公開する。失敗を記憶し、同じエンジン内では再生成しない                                            |
| 注釈・フォーム編集    | 本文の元データは保持し、編集エンジンが注釈・フォーム値を描く。表示・サムネイルを更新し、フォーム編集後のテキストを無効化する                   |
| 墨消し適用・Undo/Redo | journal から墨消し済みページを求め、適用中だけ編集エンジンへ本文・読み取り・複製を委ねる。Undo では元のテーマ変換結果を再利用できる            |
| 元データのコピー      | `GetFileData`・`SaveFileAs` は編集前の入力を返す。未保存の注釈や墨消しを保存する API ではない                                                  |
| 編集内容の保存        | `EngineMupdfSaveUpdated` が編集エンジンを保存し、UI が再読み込みする。保存元のパスは通常ファイルとメモリ由来で区別する                         |
| 複製                  | 通常は元のバイト列のコピーまたは同じファイル実体の独立ハンドル。未保存の墨消しがあれば編集エンジンを AddRef する。通常の未保存注釈は複製しない |
| 再読み込み・閉じる    | 古い表示モデルを retire し、要求を中止して描画終了を待ってからエンジン参照を返す。新文書は新しいエンジンとして開く                             |

F12 ワーカーは入力エンジンを AddRef し、その参照をキャッシュへ移すか、複製後に返す。
切り離したキャッシュは実行中のワーカーの完了まで保持し、同じワーカーが投稿した各画像の後で完了処理する。
Home の中立サムネイル生成も描画中のエンジン参照を保持する。この終了順序は変更しない。

cleanup を行う終了経路は、render cache の要求受付を止め、描画を中止し、全 worker の停止を確認してから pending controller と共有資源を解放する。
E31 で待機スレッドの HANDLE を生成直後に閉じる。描画終了待ち・UI 破棄・生成失敗時の同期破棄は維持する。
E32 の `RenderCache::Stop` は要求・起床用 lock の取得と全 worker の待機に共通の5秒予算を使い、停止失敗時は HANDLE を保持する。worker は退出前にも公開要求を解除する。
Win32 はその停止と dangerous thread の完了を確認して cleanup へ進む。dangerous thread の10秒待機と pending delete の5秒待機では UI task を処理する。
停止・完了を確認できなければ依存資源を保持して fast exit する。通常 Release の fast exit は維持する。ng も同期モデル破棄より前に同じ停止 API を使う。
通常のタブ破棄の描画終了待ちは維持する。全ての終了処理の有界性を保証する変更ではない。
同期 Reload と clean 文書の Save As はダイアログ復帰後に窓・タブ・controller・engine の同一性を検証する。
Reload はパスと engine を保持し、対象が変われば新 controller を破棄する。パスワード画面は終了通知を外側のループに戻す。

上記の PDFium の入力保持を非 PDF 全般の保証にはしない。
ファイル入力の画像・CBX・EPUB は、保存や Clone が現在の元パスを読む経路を持つ。
画像の Clone も、画素を複製する一方で描画用データを元パスから再取得する場合がある。
小さい DjVu は元パス消失後も保持データを保存できるが、Clone は元パスを優先する。
確認した入力条件と実行結果は[非 PDF の確認結果](full-review-results.md#非-pdf-の元パス依存実行確認)を参照する。

### 確認したロックの入れ子

| 経路                     | 取得順・境界                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| PDFium 描画              | `themeLock` → `gPdfiumLock` → 読み取りコールバックの `fileLock`                                                           |
| 描画プローブ・テーマ変換 | `themeLock` の内側で専用 MuPDF 文書を使用し、読み取りは `fileLock` を取る。遅延編集のロックとは共有しない                 |
| 補助リンク読み取り       | `gPdfiumLock` の内側で専用 MuPDF 文書を使用する。元データの読み取りだけが `fileLock` を取る                               |
| 編集生成                 | `editorLock` → 新しい MuPDF 文書の初期化。PDFium のロックを取ったまま呼ばない                                             |
| 編集への委譲・注釈合成   | PDFium の読み取り・描画ロックを解放してから、MuPDF の `pagesLock` → `renderLock` → `docLock` の必要な部分を取る           |
| TOC                      | PDFium で判定後にロックを解放し、編集を取得する。結果の公開時に再度 PDFium をロックする                                   |
| XMP の有無               | `xmpLock` → `fileLock`。`fileLock` を持ったまま上位ロックへ戻る経路はない                                                 |
| 最終破棄                 | `gPdfiumLock` 内で PDFium と専用プローブを閉じ、最後に編集への参照を返す。確認した MuPDF 側から PDFium への逆順取得はない |

PDFium のフォームコールバックは無処理または固定値を返し、UI や編集生成へ再入しない。
描画中止は atomic な cookie を更新し、終了を待つ側は上記のエンジンロックを保持しない。
これは対象経路のコード確認と検証結果であり、全スレッドの実行順を網羅した証明ではない。

## 読み取り API の契約

UI の hover・paint は、検索などの完全な読み取りと待機・編集エンジン生成の条件が異なる。
`EditorLoad::IfLoaded` と `EditorLoad::Load` が生成の可否を指定する。
`IfLoaded` は生成中の編集エンジンも待たず、公開済みのポインターだけを借りる。
`Load` は生成を直列化し、失敗後は同じエンジン内で再生成しない。

`HasAnnotationEditor` は遅延編集への対応可否であり、生成済み・生成成功・文書の編集権限を意味しない。
`EngineSupportsAnnotations` も機能の判定で、権限は `allowsAnnotations`・`allowsFormFilling`・
`allowsCopyingText` に別に保持する。E18 は権限の取得・適用方針を変更しない。

フォームの UI 読み取りは `PageReadResult` で取得済み・保留・既存編集エンジンへの委譲を区別する。
`Pending` は今回の hover・paint を見送り、`UseEditor` だけが既存編集エンジンを参照する。
`Ready` は空の結果も含む。他の `Try*` の戻り値は、用途に応じた既存の契約を保つ。

| API                                  | 取得・待機・生成の契約                                                         | 未取得・再試行                                                               |
| ------------------------------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `ExtractPageText` / `GetTextForPage` | 完全な検索・選択用。待機と必要な編集エンジン生成を許す                         | 編集生成が失敗した場合も PDFium の取得できた文字列を返すが、`partial` を保つ |
| `ExtractPrefetchText`                | ワーカーで待機できるが、編集エンジンを生成しない                               | 不足を `PageText::partial` で返す。`GetTextForPage` が再抽出して置き換える   |
| `TryExtractPageText`                 | PDFium・既存編集のロック競合、編集生成前のテキスト不足は `false`               | 保留・取得失敗は再試行する                                                   |
| `GetElements`                        | 完全な要素取得。必要なら編集エンジンを生成し、添付先を解決する                 | 編集・ページ取得失敗時は PDFium 側の要素を使う                               |
| `TryGetElements`                     | PDFium ロック競合は `false`。生成せず、利用できる要素を返す                    | `true` は全要素の完了を保証しない。paint・リンク再計算で再取得する           |
| `GetElementAtPos`                    | hover 用。PDFium と生成済み編集エンジンを参照する                              | ロック競合は今回のヒットを見送る。添付先は追跡時に解決する                   |
| `TryHasPageAnnotations`              | ロック競合も注釈なしも `false`                                                 | 不在の確定値として保存しない                                                 |
| `TryFormWidgetAt`                    | `Ready` は空を含む判定済み、ロック競合は `Pending`、編集生成済みは `UseEditor` | hover は新規生成せず、後続のイベントで再取得する                             |
| `TryFormHighlightRects`              | paint 用。ロック競合は `Pending`、署名状態不明・編集生成済みは `UseEditor`     | 既存編集エンジンがなければ今回は描かない。paint から生成しない               |
| フォーム・注釈の操作                 | 明示操作は `EditorLoad::Load` を許す。フォーム外のクリックは PDFium で除外する | 生成失敗・ページ未取得は既存の null / 空結果を保つ                           |

部分テキストは hover にだけ利用でき、検索・選択は必ず `GetTextForPage` の再抽出を通る。
取得済みの空ページと、保留・部分取得を区別する。編集生成失敗後も不完全な文字列を完成扱いにしない。
ページやテキストの取得失敗は `PageText::failed` で区別し、キャッシュを完成させずに後で再試行する。
`TryGetElements` の要素はエンジン所有、テキスト抽出結果は呼び出し側所有、
テキストキャッシュの文字列・座標は借用という扱いも維持する。

MuPDF の Try テキスト取得は `pagesLock` → `renderLock` → `docLock` をすべて TryLock する。
フォーム強調の MuPDF 経路も、ページ取得とその後の文書アクセスで競合時に見送る。
TryLock は待機回避であり、初回ページ解析の実行時間を制限するものではない。
非 PDF エンジンの基底 `TryExtractPageText`・`TryGetElements` は従来どおり blocking API に委譲する。
ng も共有の基底実装とフォーム結果の呼び出し側を使う。全 API の非待機化は E18 の対象ではない。

## レビューで確認した欠落

E25 時点では、自動再読み込み・元パス消失・署名途中失敗・フォームのテキストキャッシュに欠落があった。
E26–E29 でこれらを修正した。範囲と検証結果は [history.md](history.md#e26-automatic-reload-2026-11-10) を参照する。
CBX のネットワークコピーと非同期 controller 破棄の HANDLE 漏れは E30・E31 で修正した。
レビュー時点の根拠・変更案・検証範囲は [R1–R6](full-review-results.md#e25-指摘と最小変更案) を参照する。

E36 は注釈・フォームの値確定と appearance 更新を分け、後段失敗でも確定済み変更を dirty・再描画へ通知する。
E37 はページ単位で journal を確定し、失敗ページの番号を警告する。成功ページの本文・検索・Undo と PDFium の編集側への切替は維持する。
失敗ページは journal を破棄し、既存 wrapper を外してページを読み直す。再列挙に失敗した場合も不完全な wrapper を公開せず、次回読み込み時に再試行する。

E25 の[整理結果](full-review-results.md#e25-再点検)では、保存判定・ダイアログ対象検証を UI、
確定変更と dirty・描画・text の整合を共通編集層、停止結果と cleanup の判断をキャッシュ所有者へ置く。
対応内容と検証範囲は各修正の履歴を参照する。署名の失敗時取消と編集確定後の表示更新失敗は別の契約を維持する。
既存のエンジン・描画の分担と形式別の元入力契約を維持し、全面分割や全形式のスナップショット化は行わない。
E26 で自動 Reload の入口に未保存・対象ウィンドウのフォーム入力判定を置き、置換を保留する。
タブ再選択は更新待ちを先に消さず、成功した Reload が消す。他窓の入力は破棄しない。
手動 Reload コマンドは入力を確定して保存確認し、保存後の Reload・明示破棄は直接進める。
編集の受理結果・Undo 位置だけでは入れ子操作や JS の別 field 変更を表せず、署名の journal だけでは署名待ち登録と loaded page の取消を保証しない。

E29 はフォーム setter の試行後に全取得済み text cache を無効化する。
`EngineBase::TextGeneration` が PDFium の cache を editor に追従させ、抽出中の旧世代結果も捨てる。
借用中の文字列・座標は退避して engine と同じ寿命を保つ。検索は skip・継続位置と UI の件数・snippet・選択を更新する。
変更の有無を推測せず拒否時も無効化する。E36 は別途、journal 内の確定変更と表示更新エラーを通知する。
