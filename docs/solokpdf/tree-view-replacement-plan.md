# 目次とお気に入りの TreeView 置き換え計画

## 目的と範囲

Windows 版 SolokPDF の目次とお気に入りを、Win32 TreeView から共通の仮想ツリーへ移行する。項目の表示とスクロールバーを同じ描画経路にまとめ、本文とテーマやスクロールバー設定を揃える。データモデル、文書エンジン、設定形式、既存の操作は維持する。ng 版の UI は対象外とする。

現在の目次は Windows 標準のスクロールバーを使用する。以前のテーマ色の後塗りは、Windows の描画との二重描画を避けるため削除した。置き換えでは後塗りを復活させない。

## スクロールバーの仕様

| `Scrollbars` | 目次とお気に入りの動作                                       |
| ------------ | ------------------------------------------------------------ |
| `windows`    | Windows 標準のスクロールバーを表示する。                     |
| `overlay`    | 本文と同じ常時表示のバーを使用する。                         |
| `smart`      | 本文と同じ自動非表示のバーを使用する。                       |
| `hidden`     | バーを表示せず、ホイール、キー、選択項目への移動は維持する。 |

ツリーの状態をスクロール範囲・位置・表示領域の唯一の基準とする。横方向は長い項目の末尾まで移動できるようにし、大きな範囲でも位置を 16 ビットに切り詰めない。

目次と本文の下端の位置差は、現在のサイドバーの下余白 4 DIP による。項目の内側余白を保ちつつ、スクロール領域の下端を揃える方法を試作する。

## 既存基盤

- `src/shared/gui/UIModels.h` の `TreeModel` を再利用する。展開状態や、現在ネイティブ項目ハンドルに使う `userData` の扱いは見直す。
- `src/gui/VirtCtrl.h` の `VirtListBox` は可視行の描画を参考にできるが、階層表示と横スクロールは備えていない。
- `src/gui/VirtHost.h` は子ウィンドウ、描画、入力配送の土台にできる。
- `src/OverlayScrollbar.cpp` の本文用バーは再利用候補とする。縦横の同期と、標準バーの扱いは新しいツリー側で設計する。
- `src/ng/gui/Sidebar.cpp` の階層操作を参考にし、共通化できるロジックのみ抽出する。GPUI の描画コードは Windows 版へ複製しない。

## 実装手順

1. **現行動作を固定する。** 目次とお気に入りの展開、選択、検索、ページ移動、ショートカット、表示状態の保存を調べ、回帰テストを用意する。4 種のスクロールバーモードは新仕様の受け入れ条件として別に定義する。現行の目次・お気に入りには未対応のため、現行動作の成功条件にはしない。
2. **必要な準備だけをリファクタリングする。** 現行の TreeView と挙動を保ち、項目の表示、選択、展開・折り畳み、矩形取得、ヒット判定を項目単位の表示 API にまとめる。`TableOfContents.cpp`、`Favorites.cpp`、`MainWindow.cpp` の `HTREEITEM` や `TVM_*` への直接依存を減らす。イベントも Windows の通知構造体ではなく、項目・キー・操作理由を渡す形に近づける。汎用 UI 基盤や無関係な画面は整理しない。
3. **実現性を早期に確認する。** 仮想ツリーの試作で縦横スクロール、4 モード、UI Automation、DPI、RTL を調べる。読み上げ対応の制約は本格的な実装に入る前に確認する。
4. **仮想ツリーと状態管理を作る。** `VirtHost` 上に表示・ヒット判定・縦横スクロールを実装し、モデル、親子関係、展開、選択、可視行、スクロール位置を管理する。旧 TreeView の使用中は Windows 側を状態の基準とし、新部品への切り替え時に展開・選択・位置を引き継ぐ。両方の状態を長期間並行管理しない。モデル再生成後は古い項目参照を保持しない。
5. **操作とアクセシビリティを実装する。** マウス、右クリック、ツールチップ、キーボード、フォーカスと読み上げに対応する。標準 TreeView で可能な操作を移行前に確認する。
6. **目次を移行する。** `src/TableOfContents.cpp` を新しい API に切り替える。ページ追従、同一ページ項目の強調、検索、展開状態、リンク・添付ファイルの操作を維持する。
7. **お気に入りを移行する。** `src/Favorites.cpp` のサイドバーとお気に入りタブを同じ部品へ移す。文書別の階層、移動、名前変更、削除、展開状態を維持する。
8. **切り替えを完了する。** 目次・お気に入りに残る Win32 TreeView 依存を取り除く。移行中の内部切り替えは検証完了後に削除する。

各段階でビルドと対象テストを通す。移行中は旧部品へ戻せる状態を保ち、表示の置き換え後に不要なコードを整理する。

## 維持する操作と表示

左右キーによる階層移動と展開、上下、Home/End、テンキーの展開・折り畳み、文字による項目検索、F6、検索欄との移動、右クリック、ダブルクリックを現行に合わせる。目次の Enter による展開と、お気に入りの Enter による移動の違いを維持する。選択変更とページ移動は別のイベントとして扱い、クリックで二重に移動しないようにする。

初回移行は現在の一行表示とする。固定ページ番号、折り返し、検索文字の部分強調は復活させない。`ShowTocPageNumbers` と `TocWrapText` は ng との設定互換性のため残す。

RTL では表示、ヒット判定、横スクロール方向の反転を統一する。DPI 変更時はフォント幅、行の高さ、バーとヒット領域を更新する。高コントラストではシステム色とフォーカス表示を優先する。

## アクセシビリティと性能

Win32 TreeView を外すと、Windows が提供している読み上げ情報が失われる。新しい部品で項目名、階層、展開・選択・フォーカス状態、可視範囲、安定した項目 ID を公開する。UI Automation の ExpandCollapse、Selection、SelectionItem、Scroll、ScrollItem の対応範囲を検討し、Narrator と NVDA で検証する。読み上げ確認は切り替えの完了条件とする。

描画量は可視行数に比例させ、行一覧は展開・検索などの変更時に更新する。項目幅は実際のフォントで測定し、太字・斜体を含めてキャッシュする。大きな目次やお気に入りで UI が長時間止まらないようにし、深い階層の走査とモデル再生成時の参照寿命に注意する。

現行の `TreeModel::userData` はネイティブ項目ハンドルと、目次項目の実体化済み判定に使われる。準備段階で削除せず、ネイティブ側へ隠蔽する。新部品では独自の対応表と世代管理を用い、検索によるお気に入りモデルの再生成後に、選択・UI Automation・遅延処理が古い項目を参照しないようにする。

## 検証

- `toc-native-scroll`、`toc-selection-visible`、`toc-expand-chapter`、`toc-tree-sent-click`、`issue-1841`、`issue-1998`、`issue-6167` と、お気に入りの操作・検索・テーマに関する既存テストを対象とする。
- `SysTreeView32` や `TVM_*` に依存するテストは、新部品の状態を確認する API と実際のマウス・キー操作に移行する。テストを単にスキップしない。
- 4 モードの切り替え、スクロール中の描画、末尾到達、項目の展開、検索、サイズ変更、DPI、RTL、高コントラストを確認する。
- 長い目次と大量のお気に入り、モデル更新中の選択・フォーカス、Narrator と NVDA を確認する。
- ローカル GUI テストは `docs/solokpdf/testing.md` に従い、非表示デスクトップで実行する。

## 独立した設定の修正

`-for-testing` では設定パレットや詳細設定で変更した値が、保存されないまま既存ファイルから再読み込みされ、元に戻る。設定の保存と適用を分離して別途修正する。先に修正すると検証しやすいが、ツリー試作の必須条件にはしない。未修正の間は保存可能な独立 `-appdata` で設定変更を検証する。

## 試作で決めること

- UI Automation と MSAA の互換範囲。
- `windows` モードの非クライアント領域と、標準バーの配置方法。
- サイドバーの項目余白を維持しながら、本文とバーの下端を揃える方法。
- 状態管理を ng と共有できる範囲と、上流変更を取り込む際の保守方法。

実装日数は、これらの試作とアクセシビリティの範囲を確認した後に見積もる。
