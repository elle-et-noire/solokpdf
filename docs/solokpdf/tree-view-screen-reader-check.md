# TreeView の手動確認

2026-11-09 時点で実機確認は未実施（F2）。既定化した仮想ツリーが対象。Debug・Release とも同じ部品を使う。
自動テストの状況は [置き換え計画](tree-view-replacement-plan.md#試作の結果) を参照する。

自動テストとは別に、操作する人のデスクトップで実行する。

## 起動

PowerShell でリポジトリのルートから起動する。専用の PDF と設定は `.work/tree-reader-check` に作られる。
準備コマンドは専用設定を毎回上書きする。

```powershell
. ./tools/solokpdf/env.ps1 -Toolset v145
bun tools/solokpdf/tree-reader-fixture.ts
& ./out/dbg64/SumatraPDF.exe -for-testing -appdata "$PWD/.work/tree-reader-check/appdata" "$PWD/.work/tree-reader-check/tree-reader-check.pdf"
```

デバッグ版のビルドが必要な場合は、環境設定後に `bun cmd/solok-build.ts -quick` を実行する。
`-for-testing` により既存のセッションと設定は変更されない。

## 読み上げ

Narrator と NVDA を一つずつ有効にし、それぞれ以下を確認する。

1. スクリーンリーダーを有効にし、目次にフォーカスを移す。ツリー名と `First`、`Second`、`Third` の項目名・選択状態が分かることを確認する。
2. `Second` で右矢印を押し、展開状態と子項目 `Nested`、階層が分かることを確認する。左矢印で折り畳み、状態の変化を確認する。
3. Tab と Shift+Tab で目次とお気に入りの間を移動する。お気に入りのツリー名とファイル名を確認し、ファイル名で右矢印を押す。`First favorite` と `Third favorite` の項目名、階層、選択状態が分かることを確認する。
4. お気に入りで上下キーを押し、Enter で選択項目のページへ移動する。キーボードのコンテキストメニューも確認する。
5. 各ツリーの検索欄で項目を絞り込み、検索文字を消す。結果の変化と復元後の項目を読み上げられることを確認する。

各スクリーンリーダーについて、バージョン、実施結果、読み上げられなかった情報や操作を記録する。試験後は SolokPDF を閉じ、両者を別々に確認する。

## スクロールと DPI

目次・お気に入りが縦横にはみ出す文書と設定を使う。上記の小さい読み上げ用文書だけでは、バーの末尾到達を確認できない。
`-for-testing` で設定が戻る問題（E11）を避けるため、4 モードは `Scrollbars` を書いた専用 `-appdata` で個別に起動する。

| 対象      | 操作と確認点                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------ |
| `windows` | 縦横のつまみを実カーソルでドラッグする。末尾へ到達し、項目表示と位置が一致する。                                   |
| `overlay` | 縦横のバーを操作する。末尾の項目が欠けず、検索・解除・サイズ変更後も操作できる。                                   |
| `smart`   | 実カーソルでバーへ出入りする。太い表示・細い表示・自動非表示が切り替わり、隠れたバーが入力を奪わない。             |
| `hidden`  | バーが表示されず、ホイールとキーで末尾へ移動できる。                                                               |
| DPI       | 倍率の異なる実モニター間で移動する。行・文字・バーの寸法、クリック位置、ツールチップ、選択項目の可視性を確認する。 |

目次とお気に入りの両方で確認する。DPI 値の模擬変更やテスト用カーソルの成功を、実機確認の成功として記録しない。
