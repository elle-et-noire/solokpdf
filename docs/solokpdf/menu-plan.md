# SolokPDF メニュー再編計画

**Solへの依頼**　Windows版SolokPDFで、PDFを開く、読む、探す、選択してコピーする操作を短くする。以下の順に実装し、各段階で実際のWin32メニューと操作結果を確かめる。対象はアプリケーションメニューと、本文・タブ・目次・お気に入り・ホームの右クリック。基準は `solokpdf-dev` の `82f8882c1`。実装開始時のHEADとの差を先に確認する。

## 利用者から見た完成形

通常のメニューバーは左から **ファイル、表示、移動、お気に入り、ツール、設定、ヘルプ** の7項目とする。デバッグメニューは従来の表示条件に従う。以下の名称は日本語で役割を示す。実装では既存の翻訳キー、コマンド、キーボードショートカットを優先する。

| メニュー   | 直接選べる操作と、詳細項目の行き先                                                                                                                                                                                                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ファイル   | 先頭の「開く…」で設定済みのファイル選択画面が開く。新規ウィンドウ、閉じる、名前を付けて保存、印刷、プロパティ、履歴、終了を置く。URLやフォルダー内の別ファイルを開く操作は「他の方法で開く」、外部ビューアーとメールは「外部で開く・送る」、名前変更・削除などは「ファイル管理」にまとめる。                          |
| 表示       | 単ページ・見開き・連続表示、幅に合わせる・ページに合わせる、回転、全画面を直接選べる。残りの倍率とユーザー定義倍率は「ズーム」、余白・段組み・マンガ等は「ページ表示」、目次・サムネイル・ツールバー等の表示切替は「画面構成」に置く。プレゼンテーションと自動スクロールもここから辿れるようにする。                  |
| 移動       | ページ指定、前後ページ、先頭・末尾、戻る・進む、検索を維持。章移動は対象文書で利用できるようにする。                                                                                                                                                                                                                  |
| お気に入り | 現在のページの追加・解除と登録先への移動を優先。編集とタブグループはこのメニューに残す。                                                                                                                                                                                                                              |
| ツール     | 先頭はコマンドパレット。「選択」にはコピー、範囲選択、翻訳・検索・ユーザー定義処理。「読み上げ」には開始・停止と既存の音声設定。「PDF操作」には抽出・結合・署名・変換等、「計測」にはグリッド等、「文書でAIチャット」には利用可能なプロバイダーをまとめる。対象位置が必要な注釈操作は本文からも実行できるようにする。 |
| 設定       | 設定画面、テーマ、言語、ショートカットを残す。ファイル選択画面の既定値はここで変更できるようにする。設定ファイルを開く操作や利用制限は詳細項目にまとめる。                                                                                                                                                            |
| ヘルプ     | マニュアル、キー操作、バージョン情報を優先。診断表示は既存の利用条件で詳細項目またはパレットへ移す。                                                                                                                                                                                                                  |

16進表示、選択画面を指定して一度だけ開く操作などは、同じ状態でパレットから実行できればそこへ移す。検索で見つからない、引数が渡らない、選択対象が変わる場合は、元の意味に合うサブメニューに残す。未分類の既存項目にもこの手順を適用する。新しい「簡易モード」設定やツールバーの再設計はこの作業に含めない。

### 右クリックの先頭項目

| 開いた場所・状態           | 先頭または直下に出す操作                                                                                                 | 詳細操作の扱い                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PDF本文の余白、選択なし    | このページをお気に入りに追加／解除                                                                                       | ページ上なら「注釈」と「ここから読み上げ」を既存の利用条件で出す。ページ外にはページ固有の操作を出さない。                                             |
| テキスト選択               | 「コピー」→「ハイライト」。後者は注釈可能なときだけ                                                                      | 翻訳・検索・カスタム処理は「選択の操作」へ。ハイライトは選択に即適用する `CmdCreateAnnotHighlight`。                                                   |
| 矩形選択                   | 選択範囲を画像としてコピー、画像として保存                                                                               | 範囲の印刷・ズーム等は「選択の操作」へ。文字用の翻訳は隠す。                                                                                           |
| リンク／埋め込み添付       | アドレスを持つリンクなら「リンク先をコピー」、添付なら「添付を保存」                                                     | アドレスを持たない内部リンク、通常のページとの違いを保つ。                                                                                             |
| 画像                       | 「画像をコピー」「画像を保存」                                                                                           | 切り抜き・置換・外部編集・Lens等は「画像の操作」へ。単体画像とPDF内画像の対応差を保つ。                                                                |
| 既存の注釈                 | 内容があればコメント表示・コピー                                                                                         | 切り取り・貼り付け・削除等は「注釈」へ。新規作成と既存の注釈への操作を区別する。                                                                       |
| 全画面／プレゼンテーション | 「全画面を終了」とメニューバーへの入口                                                                                   | 通常時にメニューバーやツールバーを隠した場合もAlt/F10で設定に戻れることを確認する。                                                                    |
| タブ                       | 対象タブを閉じる、複製、フォルダーに表示。未保存時は保存先を選べる                                                       | 左右・他・全タブを閉じる操作は「まとめて閉じる」へ。色・グループ等はタブの詳細へ。                                                                     |
| 目次／お気に入り／ホーム   | 目次は該当章の展開・折りたたみ、埋め込み項目は開く・保存。お気に入りは対象の編集・解除。ホームは開く・固定・履歴から除く | 目次のレベル指定等は「展開」へ。ホームの履歴からの除去とディスク上のファイル削除は別の操作として明示する。各面がすでにこの条件を満たす場合は確認のみ。 |

選択中にリンクや画像と重なった場合は、既存の選択が有効なら選択操作を先頭にし、クリック対象の操作を続ける。同じコマンドは同じ階層に一度だけ置く。読み上げ位置、スニペット挿入、ページ単位のLens検索など、その場の座標に依存する機能は対象別サブメニューに残す。本文の通常の右クリックからは文書全体のPDF処理・AIチャット・画面構成を外す。利用可能な項目が消えたサブメニューと余分な区切り線は除く。

## 実装手順

1. **現状を採取する。** [メニュー定義](../../src/shared/MenuDefs.cpp)、[Win32の構築・実行処理](../../src/Menu.cpp)、[利用条件](../../src/shared/CommandAvailability.cpp)を突き合わせる。実アプリの通常PDF・選択・ホームで表示順を採取し、無効項目と非表示項目を区別する。作業用の `.work/menu-plan/` に「旧経路／コマンドIDまたは動的項目群／表示条件・対象／新経路／検証結果」の移行表を置く。上の2表に出てこない項目も、既定で隠れる項目も記録する。各段階の終了時に表を更新する。
2. **本文の右クリックを変更する。** `OnWindowContextMenu` と `BuildMenuFromDef` の選択・位置判定を使い、先頭操作を直接配置する。既存の `menuDefSelection` 等の親にだけ掛かるフィルターは移動先にも適用する。印刷・コピーの権限、編集可能性、エンジン差、未保存状態を既存判定から取得する。座標を使うコマンドは[元のクリック位置の引き渡し](../../src/shared/MenuCommon.cpp)と実行分岐を確認。メニューを閉じるまでに文書やウィンドウが変わった場合のガードを保つ。ここで本文のテストを通す。
3. **メニューバーを組み替える。** まず「開く…」と外部アプリ・履歴、次に表示・ズーム、最後に選択・読み上げ・文書操作を移す。SolokPDFのWin32ビルドだけに構成を適用する。共通の葉メニューは再利用し、[ng凍結の範囲](backlog.md#not-planned)を守る。全画面用のメニューバーのコピーにも同じ構成を使う。新しい表示場所でチェック状態とショートカットの表示を確かめる。
4. **動的更新を実際に開いて確かめる。** `UpdateAppMenu` はファイル・お気に入り・ズームを先頭IDで識別する。`RebuildFileMenu` が旧構成を復元しないこと、幅・ページ合わせ項目とズームのチェックが同期することを確認する。履歴の挿入先は `CmdExit`、外部ビューアーは `CmdOpenWithHtmlHelp`、カスタム選択処理は翻訳サブメニュー、スニペットは注釈の挿入位置に依存する。移した項目は新しい親で組み立て、初回・再表示・別タブ・別ウィンドウで検証する。読み上げはウィンドウごとのメニューハンドルと一時ポップアップを区別する。
5. **周辺の右クリックとキーボードを仕上げる。** [タブ](../../src/Tabs.cpp)、[目次](../../src/TableOfContents.cpp)、[お気に入り](../../src/Favorites.cpp)、ホームの `OnAboutContextMenu` を対象にする。非アクティブタブを右クリックし、そのタブに操作が届くことを確認する。既存のCtrl系ショートカットを保持し、トップ階層に残る項目のAltアクセスキーを可能な限り再利用する。同じ階層のアクセスキーの衝突、矢印・Enter・Esc、Shift+F10またはメニューキーによる操作、閉じた後のフォーカスを確認する。
6. **結果を記録する。** [features.md](features.md)に新しい配置と主な移動先を書く。移行表の行をすべて照合し、テスト結果・両エンジンでの差・変更前後の代表例を[history.md](history.md)に要約する。下の完了条件を満たしたら[backlog.md](backlog.md)の該当項目を閉じ、対象変更だけをコミットして現在のブランチのupstreamへ通常pushする。

## 検証の進め方

[ローカル試験手順](testing.md#local-windows-runs)に従う。各実装段階で変更したC/C++をclang-formatし、TS変更時はリポジトリ指定のフォーマッターを使う。Debugを一度ビルドし、アプリを起動する試験はサンドボックス外のhidden desktopで個別に実行する。以下は本文変更後の例。

```powershell
. ./tools/solokpdf/env.ps1
bun cmd/solok-build.ts -quick
bun tools/solokpdf/run-hidden.ts -- bun tests/ad-hoc-e123-busy-actions.ts --no-build
```

以下は各工程の対象試験。単独テスト名は `tests/<名前>.ts` として上記ランナーに渡す。工程ごとに該当分を回す。

| 工程                   | 既存試験                                                                          | 追加で確認する結果                                                                                                                             |
| ---------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 本文・選択・注釈       | `ad-hoc-e123-busy-actions`、`ctx-menu-reload`、`text-snippets`、`annot-cut-paste` | 実ポップアップの直下のIDと順序。コピーした文字列、作成されたハイライト、リンクのアドレス、画像コピーと保存内容、スニペットの挿入ページ・位置。 |
| ファイル・お気に入り   | `ad-hoc-b65-menu-owner`（履歴・お気に入り試験を含む）、`file-menu-send-by-email`  | 「開く…」が既定ピッカーを一段で開く。最近の文書・外部ビューアー・メールが再表示後も正しい文書に対して使える。                                  |
| 表示・ツール・設定     | `palette-command-availability`、`pdf-only-menu-items`                             | 標準とカスタムの倍率、テーマ、音声、選択ハンドラーを新しい親で開く。PDFと非PDF、文書なし、利用制限下で表示・実行条件を照合。                   |
| タブ・目次・キーボード | `tab-menu-close`、`toc-expand-chapter`、`ad-hoc-virtual-tree-focus`               | 複数文書・未保存タブ、目次に埋め込み項目がある文書、メニュー非表示、全画面で各対象への操作と復帰を確認。                                       |

既存試験の固定行番号や旧階層を更新する際は、期待するコマンドID・対象・結果を残す。表示可否プローブだけでは実際の深さや選択後の動作を検証できない。未カバーの本文の先頭操作とメニューバーの到達経路は既存のWin32メニューヘルパーで回帰試験を追加・拡張する。レイアウト変更は旧実装で階層・順序の期待が失敗することを先に確認する。別の不具合を直す場合も再現試験を先に置く。

## 完了条件

- [ ] 普段のPDFでは通常のトップ項目が7つ。「ファイル → 開く…」、文字選択からのコピー／ハイライト、リンク先コピー、画像コピー／保存に追加のサブメニューが要らない。本文右クリックにAIプロバイダーやツールバー設定が出ない。
- [ ] 移行表の全項目に、同じ対象・権限で使える移動先と確認結果がある。特に座標依存操作、カスタム項目、全画面からの復帰、非PDF固有操作を確認した。
- [ ] PDFium既定とMuPDFフォールバックの両方で本文操作を確認した。元から条件が異なる操作は各エンジンの基準どおり。試験内で両方を選ぶものは一度、外部指定が必要なものは `SOLOKPDF_ENGINE=mupdf` でも実行し、終了後は元の環境に戻す。
- [ ] 日本語・英語で通常／狭いウィンドウの表示とキー操作を確認した。代表例として、通常のメニューバー、本文余白、文字選択、画像の変更前後のメニューを階層付きテキストまたはキャプチャーで比較した。
- [ ] 対象試験が成功し、skipと未検証のケースを区別した。所有権・寿命を変えた場合は該当ケースをASanでも確認した。ローカル検証はDebug／必要時のASanに限り、全スイートとローカルReleaseは実行しない。
