# キーボード入力の現状と検証方針

2026-11-09 時点の入力経路と検証方針。共通化前の調査は [keyboard-handoff.md](keyboard-handoff.md) に残す。
下表はコードから読める現状と維持したい動作であり、未検証の項目を仕様確定としない。

| 対象                        | 維持したい動作                                                                                                     | 検証が必要な点                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| PDF のフレーム・キャンバス  | ユーザー定義キーを Vim・標準キーより優先する。回数・接頭キーは対象コマンドで消費し、フォーカス移動などで破棄する。 | 修飾キー、競合する文字キー、キーリピート、AltGr、デッドキー    |
| 検索欄などの Edit・ComboBox | 文字入力とキャレット操作を維持し、安全なショートカットを使う。Vim の回数・接頭キーを入力しない。                   | ユーザー定義キーの安全な範囲、IME 変換中の操作、フォーカス移動 |
| 目次の仮想ツリー            | 矢印・Home/End・Enter/Space をツリーに渡し、PageUp/PageDown は文書をスクロールする。                               | ユーザー定義キーの競合、Vim 有効時の操作                       |
| ダイアログ                  | 編集欄とダイアログ固有のキーボード操作を維持する。                                                                 | Properties、Merge PDF、モードレスダイアログの違いと IME        |
| Vim コマンド欄              | 文字入力を維持し、変換中の上下・Enter・Escape を IME に渡す。                                                      | 実際の日本語 IME、変換確定とフォーカス移動                     |

| 対象               | 通常モード                           | Vim モード                     | ユーザー定義・回数                                                                      |
| ------------------ | ------------------------------------ | ------------------------------ | --------------------------------------------------------------------------------------- |
| PDF                | 標準ショートカット                   | Vim キーと接頭キー、残りは標準 | 定義済みキーを優先。未割り当て数字は先頭の `0` を除き回数になり、対応コマンドで消費する |
| Edit・ComboBox     | 文字と編集操作はコントロールへ       | 同じ                           | 編集を妨げないショートカットは実行。数字は回数にならない                                |
| 目次               | ツリーの移動キーと文書ショートカット | Vim 専用エントリーは使わない   | ツリーの移動キー以外は定義済みキーを使う。数字は回数にならない                          |
| モーダルダイアログ | ダイアログ自身の入力ループ           | 同じ                           | 文書の回数・接頭キーを適用しない                                                        |

IME は各コントロールの処理を維持する。Vim コマンド欄の変換中は履歴・確定・キャンセルを横取りしない。

## 入力経路

`RunMessageLoop` は `PreTranslateMessage`、`MaybeTranslateAccelerator`、モードレスダイアログの `IsDialogMessage`、`TranslateMessage` / `DispatchMessage` の順に処理する。`MaybeTranslateAccelerator` は最初に `VimKeysPreTranslate` を呼び、選択や注釈などの例外処理の後、対象 HWND に応じたアクセラレーターテーブルを選ぶ。

`CreateSumatraAcceleratorTable` はユーザー定義、Vim、標準の順に追加し、重複を除く。Edit と TreeView のテーブルは安全なキーに絞り、Vim のエントリーを除く。`HandleVimKey` はユーザー定義キーとの競合を調べる。数字の回数判定は Vim モードに限定されず、登録済みアクセラレーターとフォーカスを調べる。

`3412a2174` の仮想ツリー既定化では、目次・お気に入りの `FocusHwnd()` もツリー用テーブルの選択対象にした。
標準 TreeView のウィンドウクラスだけでは仮想ツリーを識別できない。修正時の検証は
[history.md](history.md#virtual-sidebar-rollout-2026-11-09) を参照する。

ユーザー定義キーの解析と一致判定はアクセラレーター側に集約した。通常テーブルは無効な ID、グローバルキー、スクリーンショットを除き、後二者は OS のホットキーとして登録する。Vim 向け照合は従来どおり全定義を調べる。OS 登録に失敗した場合を含め、ここを同じ条件にすると既存の競合時動作が変わるため、今回は統一しない。通常テーブルの件数計算と追加の条件は共通化し、定義の分類をユニットテストで確認した。実ホットキーの競合は未検証。

回数・接頭キーはウィンドウごとに保持し、Vim 処理、コマンド実行、未処理キー、マウス、フォーカス喪失、非アクティブ化、タブ切り替えで消費または破棄される。これらを一度に移動すると順序が変わり得る。

| 状態の遷移                                      | 確認方法                                       |
| ----------------------------------------------- | ---------------------------------------------- |
| 回数に続く対応コマンドで回数を使う              | `3gg`、スクロール回数                          |
| 未対応のコマンド・未割り当てキー・Escape で破棄 | `3n`・`3f`・F24・Escape                        |
| ユーザー定義キーとの競合で破棄                  | 回数または `z` の後に定義済み `g`              |
| フォーカス喪失・タブ移動・マウスで破棄          | ページ欄への移動、タブ変更、キャンバスクリック |
| ウィンドウ非アクティブ化で破棄                  | `WM_ACTIVATE` の模擬送信                       |

フォーカスのないフレームへ直接投稿した数字は回数にならない。これは通常のキーボード入力とは別のテストであり、送信先と実フォーカスの両方を見ていることを確認する。

自動スクロール中は、検索 UI を表示していなければ数字キーをスクロール速度の変更に使う。従来はフォーカスのある文書画面で `1`〜`9` が回数指定に取られていたため、`issue-6169` で修正前の失敗を確認し、両モードで速度が変わるようにした。検索 UI 表示中は既存の回数指定を維持する。

## 集約の選択肢

- メッセージループに全判定を移す案は優先順位が見やすいが、各コントロールのネイティブ処理や IME の境界を変える危険がある。
- 入力先の分類、ショートカットの解決、回数・接頭キーの状態遷移を順に共通化し、実際の配送は各コントロールに残す案を採る。送り先 HWND と実フォーカスは別に扱う。

フレーム／キャンバスの識別、回数と Vim キーに共通する文書・フォーカス条件、ユーザー定義キーの解析、数字キーの競合判定、回数・接頭キーの一部の消費・破棄処理を共通化した。回数・接頭キーの破棄箇所と特殊モードの順序は残っている。Edit・TreeView 向けテーブルや IME を含め、挙動を固定してから変更する。

`ad-hoc-vim-keys` は検索欄の文字入力・キャレット移動とユーザー定義 Ctrl+K、目次の Down とユーザー定義 `g`、ズームダイアログの数字入力、競合するユーザー定義キー、回数の先頭と途中のゼロ、未割り当てキー、フォーカスとタブの移動、マウスクリックによる回数・接頭キーの破棄を確認する。非アクティブ化は模擬メッセージで確認する。Ctrl+F 後の模擬リピートの抑制と、キー解放による抑制の解除を別々に確認する。後者には実際には起きない順序の模擬キーを使う。`ad-hoc-count-prefix` は繰り返しフラグ付きキーでスクロールを確認する。

`keyboard-ime` は日本語 IME の入力コンテキストを検索欄と Vim コマンド欄で取得し、IME API で変換文字列を設定して確定・キャンセルする。Vim 欄では変換中フラグが立った状態で、投稿した上下・Escape・Enter が履歴やコマンド欄を変更しないことも確認する。文字列は API で設定し、キーは投稿しているため、ローマ字入力から候補を選択する実キー経路の検証ではない。実行環境で日本語 IME を利用できなければスキップし、`SOLOKPDF_REQUIRE_JAPANESE_IME=1` なら失敗する。

Ctrl+F の模擬リピートを同期せずに試したときは、読み取りが投稿メッセージの処理に先行していた。アプリ側キューを同期したテストは3回通過した。実キーによるリピートは未検証。

Win32 Debug ビルドと上記テスト、`ad-hoc-shortcuts-dialog`、`issue-1841`、`issue-5751`、`issue-5867`、`issue-5971`、`issue-6280`、`issue-6378` は通過した。ng の `test_util` は既存のビルドエラーと設定テストの基準値を修正後、通過した。

## 残る検証

1. グローバルキーやスクリーンショットは OS にホットキー登録されるため、競合時の実入力を未検証。既存の除外条件は変更していない。
2. 非アクティブ化は模擬送信であり、実ウィンドウ間のフォーカス移動は未検証。その他の特殊モードでの状態破棄も網羅していない。
3. AltGr、デッドキー、ローマ字入力からの実日本語 IME 操作、物理キーの長押しは未検証。模擬メッセージやレイアウト指定だけでは実環境の検証にならない。
