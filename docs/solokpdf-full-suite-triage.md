## Evidence and limits

- SolokPDF builds settings paths from `kAppName` in `src/shared/AppSettings.cpp`; `kAppName` is `SolokPDF` in `src/shared/Version.h`. A seeded `SumatraPDF-settings.txt` is ignored. Local `issue-1438` failed before changing the path and passed after.
- `jpeg-xl-pdf` passed standalone on the current debug build. `issue-6113` fails at Win32 capture on the hosted desktop. `issue-5944` and `issue-906` reject valid debug output because their regexes omit `screen=` and `rect=`; these are test-harness failures.
- With a corrected settings filename, MuPDF passes `issue-5329` and `issue-3731` while PDFium still fails. `lazy-tab-state-after-save` remains `no-doc` with either engine. These are separate follow-ups; no app code was changed.
- The local Windows session is locked. Cursor-dependent checks after the settings change can fail for that reason; the table records the supplied CI results.
